# Backend provider cost comparison

Researched 2026-09-06. USD list prices, excluding tax. Research for issue #21; no provider decision is made here.

Subsequent decision: the user accepted Supabase in Q5. See the [working architecture decision](../decisions/local-persistence-account-synchronization.md). The comparisons and recommendation language below preserve the evidence considered before that acceptance.

## Constraints and unknowns

The user accepted managed hosting, a $50/month backend target separate from simulation compute, Expo SQLite on devices, and backend-readable private records with restricted access. Casino sessions remain strictly private ([domain glossary](../../CONTEXT.md)). Disaster recovery is deferred; one-hour maximum data loss and 24-hour restoration remain provisional investigation targets, not verified guarantees.

Dozens of strategy authors and low hundreds of revisions per month describe publishing only. Private-account MAU, sessions, history retention, synchronization frequency, bytes transferred, and peak concurrency are unknown. No production bill can yet be predicted. Authentication is a separate decision: allowances included in a provider plan do not establish the chosen login methods or email/SMS delivery costs.

## Can each implement the accepted rules?

These are engineering assessments, not claims that a provider ships True Count synchronization automatically. The server must atomically combine revision compare-and-set, proposal/receipt, sync-feed entries and totals. It must serialize sharing withdrawal against contributions, and allowance-device transfer against grants. Every request needs account authorization and idempotency; database credentials stay server-side.

| Candidate | Assessment and remaining proof |
| --- | --- |
| Supabase | Postgres functions callable through its API and row-level security provide a direct implementation path. Put each acceptance operation in one database transaction; separate API calls are insufficient. RLS complements explicit authorization and privileges, especially around privileged functions. [Database functions](https://supabase.com/docs/guides/database/functions), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) |
| Convex | A single mutation atomically reads and writes multiple records, with optimistic concurrency control. Put authorization, revision checks, operation receipt, sync feed and totals in that mutation. Actions may call external services, but their separate mutation calls are separate transactions. The accepted conflict and allowance rules remain application code. [Mutations](https://docs.convex.dev/functions/mutation-functions), [Concurrency control](https://docs.convex.dev/database/advanced/occ), [Actions](https://docs.convex.dev/functions/actions) |
| Neon + Workers | Retains Postgres semantics with an application API we maintain. Cloudflare supports the Neon serverless driver. HTTP supports non-interactive transactions; WebSocket clients support interactive transactions, scoped to one Worker request. Choose stored SQL operations or a per-request transaction and retry serialization conflicts. No extra connection proxy is assumed in the quoted stack. [Cloudflare integration](https://developers.cloudflare.com/workers/databases/third-party-integrations/neon/), [Neon driver](https://neon.com/docs/serverless/serverless-driver) |
| Firestore + functions | Server transactions atomically update multiple documents and retry on contention. Model operation receipts, account totals and shared ownership/permission state as transaction participants. Server clients bypass Security Rules, so backend authorization is mandatory. A native offline cache does not replace the accepted SQLite outbox or conflict protocol. [Transactions](https://firebase.google.com/docs/firestore/manage-data/transactions), [Server authorization](https://firebase.google.com/docs/firestore/use-rest-api) |
| D1 + Workers | `batch()` provides rollback of the statement sequence on failure, but the documented API takes prebuilt statements: it does not expose an interactive read/JavaScript/write transaction callback. Read-dependent acceptance must be encoded in conditional SQL and constraints. A zero-row conditional update is not itself an error: receipt/feed/totals must depend on successful acceptance. Prove simultaneous retry, withdrawal/contribution and transfer/grant cases before choosing D1. Keep the atomic operation inside one database. [Batch API](https://developers.cloudflare.com/d1/worker-api/d1-database/) |

## Deferred recovery implications

- **Supabase:** Pro includes daily backups retained seven days. PITR requires at least Small compute plus the $100/month seven-day add-on: approximately **$130/month** ($25 plan + $15 Small − $10 compute credit + $100). Daily backups alone do not satisfy a one-hour loss objective. Storage objects need separate protection. [Backups](https://supabase.com/docs/guides/platform/backups), [Pricing](https://supabase.com/pricing)
- **Convex:** Professional includes periodic backups: daily snapshots retained seven days or weekly snapshots retained 14 days. Manual backups last seven days and can be downloaded. File contents are optional; code, environment variables and scheduled functions are excluded. Snapshot/restore duration depends on size. This does not establish the one-hour loss or 24-hour restoration targets. [Backup and restore](https://docs.convex.dev/database/backup-restore)
- **Neon:** Free restore history is limited to six hours or 1 GB of changes; Launch supports up to seven days, with separately billed history storage. Short retention must not be confused with recovery-point granularity. [Pricing](https://neon.com/pricing)
- **Firestore:** PITR retains document versions up to seven days. It requires billing; Iowa PITR storage is about $0.15/GiB-month, backup storage about $0.03/GiB-month, and restores $0.20/GiB. Export/read charges may apply to the selected recovery route. [PITR](https://firebase.google.com/docs/firestore/pitr), [Pricing](https://cloud.google.com/firestore/pricing)
- **D1:** Always-on Time Travel restores to a minute within seven days on Free or 30 days on Paid, with no extra history/restore fee. [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

These features establish recovery options, not guarantees for catastrophic provider failure or restoration within 24 hours. The deferred investigation must cover independent exports, credentials, object storage, account deletion and an exercised restoration procedure.

## Illustrative arithmetic, not a forecast

Assume one database, 1 GB data, 1 GB retained Neon history, 50 CU-hours/month, no excess transfer or branches, and API usage inside Workers Paid allowances. Neon Launch + Workers would be **$10.85/month**: $5 + 50 × $0.106 + $0.35 + $0.20. If compute instead runs continuously at 0.25 CU for a 730-hour month, the same example becomes **$24.90/month**. These are calculations, not workload measurements or equivalent performance comparisons. [Neon usage rates](https://neon.com/faqs/postgres-services-free-to-production), [Recovery history pricing](https://neon.com/pricing), [API pricing](https://developers.cloudflare.com/workers/platform/pricing/)

Under its included API/database usage, D1 + Workers would be $5/month; Supabase Pro would be $25/month without PITR. Authentication delivery, external file storage, independent backups and operational effort still need pricing. The cheapest nominal option is not yet established for the actual workload.

## Decision input

The user is leaning toward Supabase because they know it better than Neon. Recommend Supabase as the leading candidate: that familiarity reduces integration and operational uncertainty, and its $25 base remains within the accepted $50 target. Neon's possible savings are workload-dependent and do not by themselves justify switching. Convex is another credible integrated backend, with a lower fixed floor on Starter; Neon + Workers remains a Postgres alternative, D1 + Workers requires a transaction-design proof, and Firestore uses a document model and operation billing. No provider is selected.

Before a final choice, obtain private-account activity and retention assumptions, count requests and billable database work for one representative synchronization flow, and test the concurrency cases above. Compare total database/API/storage/backup/auth cost against $50, plus the solo operator's integration burden.

## Convex versus Supabase

Convex's appeal is its TypeScript function API and reactive query subscriptions; React Native uses its React client. This is a different application programming model from Supabase's Postgres functions and RLS. Convex mutations provide a credible transaction boundary for our accounting and synchronization operations. [React client](https://docs.convex.dev/client/react/overview), [React Native](https://docs.convex.dev/client/react-native), [Mutations](https://docs.convex.dev/functions/mutation-functions)

The documented client retries mutations and supports temporary optimistic updates. That does not establish our required durable SQLite state, pending-upload recovery after process termination, or custom conflict resolution. Convex's own local-first example adds Automerge and a persistence adapter for edits that survive restarts. Engineering assessment: retain the accepted SQLite/outbox contract with either provider; reactive subscriptions alone do not remove this work. [Client guarantees](https://docs.convex.dev/client/react/overview), [Convex local-first example](https://stack.convex.dev/automerge-and-convex)

For Convex cost estimates, count subscription updates as function calls as well as explicit calls, scheduled work and file accesses. Database I/O measures document/index traffic between functions and the database. Query/mutation compute is not separately charged on serverless plans; action compute is. File storage and egress are additional meters, and backup storage/generation/restoration consume those resources. Starter includes 1 GB of file storage and 1 GB/month egress, then charges $0.033/GB-month and $0.132/GB respectively; Professional includes 100 GB and 50 GB/month, then $0.03 and $0.12. These are US rates; EU prices are 1.3 times US prices. [Resource definitions and rates](https://docs.convex.dev/production/state/limits)

Recommendation, not a recorded architecture decision: prefer Supabase given the user's familiarity and the direct Postgres implementation path for our transaction requirements. Convex deserves selection if its reactive TypeScript workflow proves a meaningful development advantage, or a measured Starter workload materially reduces the bill. Its Professional plan does not offer a lower one-developer subscription than Supabase Pro, and neither provider's daily backup feature alone resolves the deferred recovery requirement.
